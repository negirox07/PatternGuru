Creational patterns — how objects are made

Singleton

Ensure a class has only one instance while providing a global access point to it. Useful for shared configuration and connection pools, and widely overused everywhere else.

Factory Method

Provide an interface for creating objects in a superclass, but let subclasses decide which concrete type gets created.

Builder

Construct complex objects step by step, so the same construction code can produce different representations without a constructor that takes twelve arguments.

Structural patterns — how objects are composed

Adapter

Let objects with incompatible interfaces collaborate by wrapping one in a translation layer the other already understands.

Decorator

Attach new behaviour to objects at runtime by placing them inside wrapper objects, instead of growing a subclass for every combination of features.

Facade

Provide a simplified interface to a complex library, framework, or set of classes, so callers depend on one small surface rather than many moving parts.

Behavioural patterns — how objects communicate

Observer

Define a subscription mechanism so multiple objects are notified about events happening to the object they are watching. The foundation of most event and reactive systems.

Strategy

Define a family of algorithms, put each in its own class, and make them interchangeable at runtime — the standard cure for a long branching conditional.

State

Let an object change its behaviour when its internal state changes, so it appears to change class. Structurally similar to Strategy, but with a different intent.
