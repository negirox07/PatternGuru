About PatternGuru

A free reference for software design patterns

Most developers meet design patterns twice: once as a wall of UML diagrams in a textbook, and again in a code review where someone says "this should be a Strategy." Neither moment actually teaches you when to reach for a pattern. PatternGuru exists to close that gap — it is a working reference you can read in an afternoon and come back to when you are mid-task.

What the site covers

PatternGuru documents nine of the most widely used patterns from the Gang of Four catalogue, grouped the way the original book grouped them:

  • Creational Singleton, Factory Method, Builder — how objects come into existence.
  • Structural Adapter, Decorator, Facade — how objects are composed into larger structures.
  • Behavioural Observer, Strategy, State — how objects communicate and divide responsibility.

How it is meant to be used

Every pattern page carries the same structure so you can move between them without relearning the layout: the problem the pattern solves, a plain-language explanation, runnable code in TypeScript, Python and Java, the trade-offs worth knowing before you commit, and a short quiz to check that it actually landed.

Beyond the individual pages, the site includes:

  • Comparison mode — put two patterns side by side, which is the fastest way to see why Strategy and State look identical on a class diagram but differ completely in intent.
  • A knowledge quiz — randomised questions drawn across the whole catalogue.
  • Per-pattern notes — a scratchpad for your own project-specific notes, saved in your browser.
  • Keyboard navigation and voice commands — press ? for the shortcut list.
  • Accessibility options — light, dark and high-contrast themes, and a print/PDF-friendly stylesheet for offline reading.

Who builds it

PatternGuru is built and maintained by Mukesh Singh Negi, a software engineer. It is an independent side project, not the product of a company or a course provider. The source is public on GitHub.

Editorial approach

Explanations are written from scratch rather than paraphrased from the GoF book, and every code sample is written to compile and run rather than to look good in a screenshot. Where a pattern is genuinely overused in modern codebases — Singleton being the obvious example — the page says so instead of presenting it neutrally. The aim is a reference that a working engineer trusts.

How it is funded

The site is free and has no paywall, subscription, or account. Hosting and time are paid for by advertising through Google AdSense. Ads are kept out of the reading column of the pattern text itself. What that means for your data is set out in the privacy policy.

Corrections

If a code sample is wrong or an explanation is misleading, that is worth fixing — please report it.
